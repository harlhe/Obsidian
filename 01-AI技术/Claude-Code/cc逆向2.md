# Claude Code 逆向笔记 2：控制流与编排引擎

## 概念
编排引擎负责把“自然语言目标”转成“可执行动作序列”，并在失败时自动调整路径。

## 机制/流程
- 任务拆解：识别依赖关系与关键路径。
- 动作编排：读文件、执行命令、改文件、验证。
- 状态推进：每一步写入可追踪状态。
- 失败回路：重试、降级、人工接管。

## 学习要点
- 编排不是固定脚本，要支持条件分支。
- 状态机比隐式流程更可维护。
- 执行器需要资源预算控制（token/time/tool quota）。

## 高频面试问答
- Q：如何判断编排是否合理？
  A：看关键路径长度、失败恢复率、平均完成时长。
- Q：为什么需要 checkpoint？
  A：避免长任务中断后从头再来。

## 易错点
- 并行任务共享写路径导致冲突。
- 未定义回滚策略。
