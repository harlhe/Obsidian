# Claude-Code 业务补充

## 概念
业务补充的目标是把“技术能力”映射到“业务价值”，明确哪些能力直接提高交付效率和质量。

## 机制/流程
- 需求输入 -> 场景拆解 -> 能力匹配 -> 成本收益评估 -> 试点验证。
- 重点衡量：需求响应时间、缺陷率、回归效率、文档一致性。

## 学习要点
- 先找高频、重复、可标准化场景切入。
- 把指标写进方案：如缺陷定位耗时降低 30%。
- 技术方案必须带失败兜底。

## 高频面试问答
- Q：怎么判断 AI 改造是否值得？
  A：看 ROI：节省工时、提升稳定性、可持续维护。
- Q：业务补充为什么重要？
  A：它决定技术方案是否能落地，而不是停留在 demo。

## 易错点
- 只讲模型能力，不讲组织流程改造。
- 缺少度量基线，无法验证效果。

## 实战演练清单
- 用一个真实任务做 30 分钟限时复盘：先写目标、再写步骤、最后写结果与改进点。
- 把当前主题抽成 3 个“可复述模板”：定义模板、排障模板、面试回答模板。
- 记录一次失败样例：失败现象、根因、修复策略、可复用经验。

## 复习节奏建议
- D1：通读全文，口述核心概念（3-5 分钟）。
- D3：只看“高频问答”和“易错点”，做一次自测。
- D7：结合实际项目或面试题，写一页应用案例。
- D14：回看旧结论，删除过时信息并补充新实践。

## 自测题（可直接口述）
1. 这个主题最关键的工程权衡是什么？
2. 如果要落地到你的项目，第一步应该做什么？
3. 如何定义这个主题“做成了”的验收标准？
