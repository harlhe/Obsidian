# 面经总览（可复习版本）

## 概念
面经不只是“题目记录”，而是“问题 -> 回答 -> 复盘改进”的闭环资料。

## 机制/流程
1. 记录面试问题（按技术域分类）。
2. 写当场回答（原始版本）。
3. 写标准答案框架（结构化版本）。
4. 记录改进点与下一轮练习计划。

## 学习要点
- 重点准备高频主线：项目、架构、并发、数据库、故障处理。
- 每道题用“结论先行 + 原理解释 + 实战案例”表达。
- 复盘要形成可执行 action item。

## 高频面试问答
- Q：如何介绍一个你做过的复杂项目？
  A：背景/目标 -> 方案 -> 关键权衡 -> 结果与指标 -> 复盘。
- Q：回答不会的问题怎么办？
  A：先给边界判断，再给可验证思路，避免硬编。

## 易错点
- 只背定义，不会结合项目场景。
- 回答过长，缺少结论与重点。

## 实战演练清单
- 用一个真实任务做 30 分钟限时复盘：先写目标、再写步骤、最后写结果与改进点。
- 把当前主题抽成 3 个“可复述模板”：定义模板、排障模板、面试回答模板。
- 记录一次失败样例：失败现象、根因、修复策略、可复用经验。

## 复习节奏建议
- D1：通读全文，口述核心概念（3-5 分钟）。
- D3：只看“高频问答”和“易错点”，做一次自测。
- D7：结合实际项目或面试题，写一页应用案例。
- D14：回看旧结论，删除过时信息并补充新实践。

## 自测题（可直接口述）
1. 这个主题最关键的工程权衡是什么？
2. 如果要落地到你的项目，第一步应该做什么？
3. 如何定义这个主题“做成了”的验收标准？
