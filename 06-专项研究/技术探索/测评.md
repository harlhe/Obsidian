# Agent/自动化方案测评框架

## 概念
测评不是只看“能不能跑”，而是要评估稳定性、成本、可维护性和业务价值。

## 机制/流程
1. 定义任务集（正常流、异常流、边界流）。
2. 定义指标（成功率、平均时长、重试次数、人工介入率）。
3. 多轮执行，记录方差。
4. 输出结论：推荐场景、风险场景、改进优先级。

## 学习要点
- 指标要同时覆盖质量和效率。
- 同一方案至少跑 3 轮，避免偶然性。
- 评测报告必须包含失败样本。

## 高频面试问答
- Q：如何比较两种 Agent 方案？
  A：统一任务集和环境后对比成功率、成本、恢复能力。
- Q：评测最容易被忽视的指标？
  A：人工兜底成本和问题定位时间。

## 易错点
- 只选擅长场景做评测。
- 报告没有可复现实验步骤。

## 实战演练清单
- 用一个真实任务做 30 分钟限时复盘：先写目标、再写步骤、最后写结果与改进点。
- 把当前主题抽成 3 个“可复述模板”：定义模板、排障模板、面试回答模板。
- 记录一次失败样例：失败现象、根因、修复策略、可复用经验。

## 复习节奏建议
- D1：通读全文，口述核心概念（3-5 分钟）。
- D3：只看“高频问答”和“易错点”，做一次自测。
- D7：结合实际项目或面试题，写一页应用案例。
- D14：回看旧结论，删除过时信息并补充新实践。
